# 画像 → 排序 → 输出

学生答完访谈后，用 `scripts/recommend.mjs` 从该专业的成稿活法里挑出最贴合他的几条，并给出排序理由。**内容不是新写的，是已有的成稿数据按画像筛选排序**——这样既保证质量，也保证不同学生看到的结果不一样。

## 一、跑脚本

```bash
node scripts/recommend.mjs --profile "<中间产物目录>/profile.json" --out "<结果产物目录>/<专业>-我的N种活法.html" --top 5
```

- 输出 JSON：`ok`、`major`、`college`、`total`、`chips`、`ranked[]`（name / family / fit / score / oneline / why）、`rest[]`（未入选的活法名）、`out`。
- exit 3 表示专业不在库内，返回体带 `available` 清单：转成 Q1 的选项让学生重新选，或按 SKILL 第五节现写数据。
- `--top` 不给时默认 5 条；学生明确想多看几条再给 6~8。

脚本的排序逻辑（学生问"为什么这几条"时可照此解释，不要说是随机或 AI 感觉）：

| 加权项 | 作用 |
| --- | --- |
| 学生原话命中活法文本 | +2.5 / 词 |
| 语义近义词组命中（孩子/内容/设计/技术/沟通/稳定/创业/动手/研究/英语） | +1.5 / 组 |
| 想要稳定、编制、公办 | 公共编制类 +7，商业运营类 −2，内容自媒体类 −1 |
| 想要自由、创业 | 自主创业类 +5，内容自媒体类 +4，编制类 −2 |
| 想要收入上限 | 创业/内容类 +3 |
| 想要成长挑战 | 复合型、升学转轨类 +2 |
| 意向城市出现在活法文本里 | +2 |
| 命中"想避开"的词 | −6 / 词 |

## 二、对话输出（必须先给）

结构固定，按这个顺序：

1. **一句话画像**：把 `chips` 连成一句话，让学生看到"我是被这样理解的"。
2. **速览表**：`| 活法 | 一句话 | 匹配度 |`，只放 ranked 的前 3~5 条。
3. **前三名各展开一小段**：为什么排在这里（直接用 `why`）、门槛、下一步动作。不要把所有条目都展开，学生要深挖再展开。
4. **一句收尾**：还有哪几条没进前五（`rest`），他要看可以说。
5. 附页面文件链接。

写法要求：

- `why` 可以润色成口语，但**不许增加脚本没给出的判断**（比如"这个行业未来五年会涨"）。
- 匹配度用 `最匹配 / 较匹配 / 可作备选` 三档，不要自己发明百分比分数。
- 明确说这是个性化排序参考，不是"你只能做这些"。

## 三、页面输出

- 文件名：`<专业>-我的N种活法.html`，与全校通用的 `<专业>-专业的N种活法.html` 区分开。
- 页面与通用版同一版式，只多了三处：标题下的画像标签行（chips）、卡片标题右侧的匹配度标签、卡片内容首行的「为什么适合你」。
- 没有 `fit` / `why` 字段的旧数据仍按原样渲染，向后兼容。
- 生成后自检：`ok: true`、文件存在且大于 12 KB、文件内无 `__TITLE__` / `__MAJOR__` / `__DATA__` 残留、页面含"为什么适合你"。

## 四、边界

1. 排序只影响展示顺序和取舍，**不改写成稿事实**（薪资、编制、名额口径照旧）。
2. 学生画像与所有活法都冲突时（比如想留在没有该岗位的县城、又避开了所有相关方向），如实说"这几点放在一起不好同时满足"，并指出冲突在哪，不要硬推一条。
3. 学生问"哪条最赚钱/最容易"，不要给单一答案，指出各条的收入结构与代价差异。
4. 学生要求加一条库里没有的活法：可以补，但必须走 SKILL 第三节的字段与事实纪律，补完写回 `assets/majors/<专业>.json` 后再跑脚本，这样下次别人也查得到。
